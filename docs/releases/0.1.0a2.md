# DataVouch 0.1.0a2

Private alpha for acceptance testing. The repository remains private. A Git tag identifies the reviewed source; no package registry publication is included.

## What users can do

Start with **Example walkthrough** to understand how a fast ticket-sales query can still report the wrong total. On the same page, **Start your journey** explains how to create the first experiment with real workload evidence. The example uses synthetic bookings and links measured reports when available; it never invents a completed validation.

Use the UI or CLI to register workloads, select comparable BigQuery executions, declare a change, evaluate correctness, performance and reliability, and retain reproducible PASS, FAIL or UNKNOWN reports. Financial assessments use supplied pricing and billing evidence. Deployment-approved cloud project and observed location discovery uses backend credentials and preserves user scope restrictions.

Client-hosted deployment includes Docker Compose, a Helm chart, an existing OIDC gateway integration, roles, audit history and admin deletion. Python 3.15 is required. See [installation](../../README.md), [the walkthrough](../ticket-sales-walkthrough.md) and [deployment guidance](../deployment.md).

## Compatibility and upgrade

Existing report schema identifiers remain unchanged. Stable API compatibility is not promised during alpha. The bundled demo now uses the ticket-sales workload identity; existing saved reports are not migrated or deleted. Back up the stopped run store before upgrading, retain the previous image and configuration, and follow the deployment recovery procedure if acceptance fails. Use the Helm chart version 0.1.0-alpha.2 with application version 0.1.0a2 and an explicitly selected immutable image.

## Required release evidence

Before tagging, require all self-hosted checks on the PR and merged main revision: formatting, lint, types, source security, dependency audit, unit/contract/integration tests, coverage, artifact boundaries, clean installation and source/wheel parity. Retain artifact SHA-256 hashes from scripts/check_release.py with the exact reviewed wheel and source archive. Tag only the merged commit after its checks pass.

## Acceptance still required

- Real client OIDC provider, TLS, logout/revocation, credential rotation and network isolation.
- Client storage backup/recovery and representative workload accuracy, noise and overhead validation.
- Independent onboarding, adapter-author, security/source-history, financial-method and license/ownership review.
- Isolated public-contribution CI and enforceable repository protections before publication.

Record actual evidence using the [review pack](../review-pack.md) and [review record](../review-record.md). Resolve findings, then obtain explicit public-release approval. Automated tests and a test-project demonstration do not substitute for those reviews.
