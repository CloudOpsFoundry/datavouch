# DataVouch 0.1.0a2

Historical private alpha for acceptance testing. The immutable tag predates the current neutral aggregation demonstration. The repository remains private; no package registry publication or production approval is implied.

## Delivered scope

The UI and CLI register workloads, select comparable BigQuery executions, declare a change, evaluate correctness, performance and reliability, and retain reproducible PASS, FAIL or UNKNOWN reports. Financial assessments use supplied pricing and billing evidence. Deployment-approved cloud project and observed location discovery uses backend credentials and preserves user scope restrictions.

Client-hosted deployment includes Docker Compose, a Helm chart, an existing OIDC gateway integration, roles, audit history and admin deletion. Python 3.15 is required. See [installation](../../README.md), [the current aggregation walkthrough](../aggregation-walkthrough.md) and [deployment guidance](../deployment.md). Use instructions from the same source revision as the installed package.

## Compatibility and upgrade

Existing report schema identifiers remain unchanged. Stable API compatibility is not promised during alpha. The current unreleased example changes its workload identifier, output fields and CLI option to use neutral numeric groups. Regenerate sample catalogs rather than mixing old and new examples; existing saved verification reports are not migrated or deleted.

Back up the stopped run store before upgrading, retain the previous image and configuration, and follow the deployment recovery procedure if acceptance fails. This tag uses Helm chart version 0.1.0-alpha.2 and application version 0.1.0a2. Select an explicitly reviewed immutable image.

## Release evidence and remaining acceptance

All five self-hosted main CI jobs passed for tagged commit `02943dad359fe912078dd436b5a511d7cc5ff270`. Later development must pass its own revision checks and must not overwrite this tag or its artifacts.

Real client identity, TLS, network, credential rotation and recovery acceptance remain pending, along with representative workload validation and independent onboarding, adapter-author, security, financial-method and ownership/license reviews. Public CI isolation and owner publication approval are separate requirements.

Use the [review pack](../review-pack.md), [dependency-license assessment](../dependency-licenses.md) and [review record](../review-record.md). Automated checks do not substitute for these reviews.
