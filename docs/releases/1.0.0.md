# DataVouch 1.0.0

DataVouch 1.0.0 publishes the application source and setup instructions. Automated checks and local Docker testing passed. Validate your own environment before production use.

## Supported scope

- BigQuery job metadata collection and explicit baseline/candidate experiments.
- Correctness evidence, performance, reliability and financial assessments with PASS, FAIL and UNKNOWN results.
- Deterministic reports, saved history, CLI replay and CI policy gates.
- Authenticated UI, gateway-provided roles/scopes, audit and history deletion.
- Docker Compose and Helm deployment definitions, and versioned adapter contracts.

Use [getting started](../getting-started.md) and the [aggregation example](../aggregation-walkthrough.md). Other cloud adapters, automatic correctness-query execution, billing API collection and distributed high availability are not supported features of 1.0. See [product acceptance](../product-acceptance.md) for the implementation mapping.

## Distribution and compatibility

Source and release notes only. No wheel, container image or CI artifact is uploaded. GitHub automatically provides source archives for tags. Build packages and images locally when required. Local context, VM provisioning scripts, credentials, runner infrastructure and validation evidence are excluded from Git and distributions.

The package requires Python 3.15. Supported report and adapter contracts retain their explicit schema versions; incompatible changes require a new contract or major product release. Shared deployment requires one owner for the persistent store and an existing validated OIDC gateway.

## Validation boundaries

Automated tests, static analysis, dependency auditing, package installation and deployment manifest checks provide engineering evidence. Real-client OIDC/TLS/network enforcement, storage recovery, representative workloads and independent security/onboarding/license-method reviews have not all been completed. The deployment owner must perform the [client acceptance procedure](../client-validation.md) before shared production use. Passing tests do not prove realized savings or every business assertion.

Historical private CI runs and artifacts were removed with owner authorization before publication. Existing source history and release tags were preserved. Public validation runs on disposable GitHub-hosted runners without cloud credentials or artifact uploads.
