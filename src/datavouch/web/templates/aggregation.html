EXAMPLE WALKTHROUGH · WEIGHTED AGGREGATION

Would you approve this query change?

Explore how DataVouch evaluates a query rewrite using generated numeric data. A query can run successfully and still calculate the wrong result.

1. Agree what must stay correct

This example generates 1,000 groups. Each group contains three samples with values 45, 75 and 120 and respective weights 1, 2 and 3. The weighted sum is 555 per group, or 555,000 units overall.

The rule is sum of weight × sample value. All inputs are synthetic integers. This example has no currency, industry-specific rules or client data.

2. Compare three proposed decisions

CandidateWhat changes?Correctness evidenceWhat should the reviewer do?
Equivalent rewriteAggregate sample rows once instead of calculating each group separately.Still 555,000. Weights are preserved.Approve only if measured performance, correctness and reliability all pass.
Incorrect rewriteSum sample values and omit their weights.240,000. The result is 315,000 below the expected total.Reject the candidate because the weighted-total check fails, even if it runs faster.
Evidence missingUse the equivalent candidate, but omit its independent weighted-total check.Correctness has not been established for the reviewer.Hold approval. Missing evidence is UNKNOWN, not PASS.
See the important SQL difference

Equivalent calculation:

SELECT SUM(weight * sample_value) FROM samples

Incorrect calculation:

SELECT SUM(sample_value) FROM samples

Both statements can execute successfully. Only the first implements the specified calculation.

4. Start your journey

  1. Define your expected calculation, input snapshot and comparison policy, including any missing-value or duplicate-handling rules.
  2. Run the original and proposed queries against comparable input data. Keep the job IDs and UTC execution windows.
  3. Have an independent check establish the correct result for the candidate executions.
  4. Create an experiment, select the approved project and location, supply those executions and evidence, and review the recommendation.

The benefit: an engineer and reviewer share a repeatable, inspectable reason to accept, reject or postpone a query change before downstream systems depend on it.

DataVouch reads execution metadata and evaluates supplied correctness evidence. It does not independently run your assertions or prove financial savings. The BigQuery example executes in your approved project; local SQLite timing is not a BigQuery benchmark.
