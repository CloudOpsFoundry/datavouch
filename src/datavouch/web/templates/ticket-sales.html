EXAMPLE WALKTHROUGH · EVENT TICKET SALES

Would you approve this query change?

Explore how DataVouch evaluates a query change using a synthetic ticket-sales example. Your event’s sales dashboard needs to become faster. Before releasing a rewritten query, make sure it still counts every ticket in every booking.

1. Agree what must stay correct

In this generated example, 1,000 confirmed bookings each contain one standard ticket at €45, two premium tickets at €75 and three VIP tickets at €120. That is six tickets and €555 per booking, or €555,000 in ticket sales.

The business rule is sum of ticket quantity × ticket price. Amounts are stored as integer cents. This example excludes cancellations, refunds, fees and taxes; it is not a settlement or accounting-revenue calculation. It uses synthetic data, not a client’s sales.

2. Compare three proposed decisions

See the important SQL difference

Equivalent calculation:

SELECT SUM(quantity * ticket_price_cents) FROM tickets

Incorrect calculation:

SELECT SUM(ticket_price_cents) FROM tickets

Both statements can execute successfully. The second one answers the wrong business question.

4. Start your journey

  1. Define your metric and business rule. Decide how cancellations, refunds, fees, taxes, currency and settlement timing should be handled.
  2. Run the original and proposed queries against comparable input data. Keep the job IDs and UTC execution windows.
  3. Have an independent check establish the correct sales total for the candidate executions.
  4. Create an experiment, select the approved project and location, supply those executions and evidence, and review the recommendation.

The benefit: an engineer and reviewer share a repeatable, inspectable reason to accept, reject or postpone a query change before it affects an event-sales dashboard.

DataVouch reads execution metadata and evaluates supplied correctness evidence. It does not independently run your business assertions, calculate settlements, or prove financial savings. The BigQuery example executes in your approved project; local SQLite timing is not a BigQuery benchmark.
